## M5 재검증

`npm run zip:lounge`가 빌드 후 로컬 `pokemon-study-lounge.zip`을 생성했습니다. 44개 파일, ZIP 약 2.26MiB, 압축 해제 약 6.00MiB로 500개·30MiB 제한 이내입니다. ZIP 항목은 모두 상대경로이고, 압축 안의 `config.js`는 0바이트입니다. 현재 로컬 파일의 SHA-256은 `98a4ee66369e658ea76ac1a58995708e4e50b96ee85dc44d4721361b09425a58`입니다. ZIP은 빌드 산출물로 Git에서 제외하며 T31에서 최종 배포본을 다시 생성합니다. 임시 패키지에 501개 파일·31MiB 파일·절대 HTML 주소·심볼릭 링크를 각각 넣어 생성기가 거부하는 것도 확인했습니다.

`npm run check:lounge`는 ZIP을 실제 압축 해제해 `/class/game/` 하위 URL과 자체 호스트 연결만 허용하는 CSP에서 새 게임·내장 문제 풀이·저장 복구·문제 미리보기를 실행했습니다. 외부 요청과 콘솔 오류는 0개입니다. Chromium이 manifest를 파싱할 때 오류가 없었고 이름 `포켓몬 공부 대모험`, `display: standalone`, 상대 `start_url`을 확인했습니다. manifest의 192×192·512×512 PNG와 180×180 Apple 터치 아이콘 요청도 성공했습니다. 실제 iOS/Android 홈 화면에 추가해 표시되는 모습은 아직 실기기에서 확인하지 않았습니다.

[선생님·학부모 안내서](TEACHER_GUIDE.md)의 보호자 진입, 하루 진도·과목 설정, 수학 시작 진도를 두 번째 레슨으로 바꾼 뒤 `m11-u1-l2`가 활성화되는 동작, 문제 미리보기 새 탭, 학습 리포트, 이어하기 코드 입력 취소와 설정 저장을 가로·세로 E2E로 대조했습니다. ZIP 기기 저장과 Supabase 연결 웹 주소의 클라우드 저장·코드 기능 차이도 안내서와 구현이 일치합니다. 단계 6 체크포인트는 `c6b8c3e`입니다.

`config.js`는 배포 후 교체 가능한 일반 스크립트이므로 Vite가 번들에 포함하지 않는다는 안내 두 줄을 출력합니다. 파일은 그대로 배포되며 ZIP에서는 비웁니다. 빌드 오류는 아닙니다.

E2E는 실제 DOM 버튼·키보드·문제 카드로 스타팅, 라이벌, 포획, 도장 4개, 웅, 배지, 3번도로 개방, 재접속, 오답 기절 복귀를 검사합니다. 대사는 `fastText`, 문제는 `autoAnswer`로 가속합니다. 지역 사이의 긴 이동 일부는 debug teleport로 준비하며, 모든 이동을 손으로 걸은 실기기 검증이라는 뜻은 아닙니다. 침실 이동, 오박사 경계 이벤트, 3번도로 경계는 실제 키보드로 통과합니다. 도장/배지는 테스트에서 값을 직접 넣지 않고 문제 풀이와 전투로 획득합니다.

50개 화면은 1024×768·768×1024·1280×800·820×1180·375×667에서 타이틀·월드·대화·도감·파티·가방·오늘의 공부·보호자·전투·문제 카드를 촬영했습니다. 페이지/패널 가로 넘침, 스테이지 경계, 전투 명령 영역을 자동 검사하고 전체 합성 스크린샷을 직접 확인했습니다. 도감·보호자 메뉴의 내부 세로 스크롤은 의도된 동작입니다. 생성 위치: `test-results/screens/`.

## 성능과 남은 현장 검증

Darwin arm64 개발 PC의 Playwright 1.63.0 / headless Chromium 153, 1024×768, Vite 개발 서버에서 첫 타이틀 준비 142ms, 리소스 전송 3.57MiB, 월드 180프레임 간격 중앙값 16.7ms·p95 16.8ms를 측정했습니다. 강제 GC 후 JS 힙은 월드 시작 5.5MiB, 20초 뒤 5.6MiB였습니다. 이 짧은 로컬 측정은 태블릿 전체의 60fps나 장시간 메모리 안정성을 보장하지 않습니다. 실제 iOS Safari의 TTS·음악·홈 화면 설치도 아직 확인하지 않았습니다.

Supabase 실제 익명 로그인·RLS·코드 이전·오프라인 재연결은 프로젝트 준비 후 T29에서 검증해야 합니다. 네트워크 모듈 테스트와 오프라인 실행 통과를 실제 온라인 검증으로 대신하지 않았습니다. T28·T30·T31의 계정 작업과 공개 배포도 남아 있으므로 M6와 전체 출시 DoD를 닫지 않았습니다. 설치형 서비스 워커는 요구된 manifest/아이콘 범위 밖이며 제공하지 않습니다.

## 두 번째 장 검증 (2026-10-01)

회색배지 저장에서 3번도로 → 달맞이산 앞쪽·안쪽 → 4번도로 → 블루시티의 실제 맵 경계 입력과 역방향 귀환을 가로·세로 화면에서 확인했습니다. 연구원 부탁, 삐삐, 로켓단, 수첩 반환과 상처약 2개, 도장 7/8개 조건, 이슬 승리와 블루배지, 배지 연출 도중 새로고침 후 재개를 E2E로 확인했습니다. 이 시나리오는 첫 배지까지의 저장을 시험용으로 준비하지만, 새 장의 필수 사건과 배지 완료 플래그는 직접 주입하지 않습니다. 문제의 정답 선택은 E2E 가속 기능을 쓰고, 도장 5~8개는 실제 문제 카드로 얻습니다. 영어를 끈 한 과목 설정으로도 진행했습니다.

로켓단 패배 시 연구원 회복 지점으로 돌아가 승리 기록 없이 재도전했습니다. 단위 검사에서는 로켓단 승리 뒤 수첩 보상 대화가 중단되어도 상처약이 한 번만 지급되는지, 7종 스타팅에 따라 블루시티 라이벌의 첫 포켓몬이 바뀌는지 확인했습니다. 기존 첫 장의 스타팅·포획·웅·기절 복귀 E2E와 모의 카카오·라운지 계정 저장 및 이름 표시 검사도 통과했습니다.

운영 도메인의 분리된 게스트 브라우저 두 개에서는 이상해씨·꼬부기 각각 Lv.15와 누적 도장 8개 조건으로 로켓단과 이슬을 모두 이겨 블루배지를 받았습니다. 정답 선택은 E2E 가속 기능을 사용했으며, 이 검사는 스타터 종류·포획 여부가 승리의 필수 조건이 아닌지만 확인합니다. 아동의 실제 조작·음성 사용성은 실기기 확인이 남아 있습니다.

`npm run build`, `npm test`(7파일·95개), `npm run check:maps`(25맵·8계약), `npm run check:pokemon`(251종·753 아틀라스 셀), `npm run check:questions`(6,906문제·266레슨)가 통과했습니다. `npm run e2e`는 30개 통과, 중복 화면 실행 10개 생략입니다. 새 대화·전투·배지·지도는 1024×768, 768×1024, 1280×800, 820×1180, 375×667에서 화면 경계를 검사하고 이미지로 확인했습니다. Playwright 터치 에뮬레이션에서는 짧은 방향키 탭, 연구원 선택, A 버튼 대화를 확인했습니다. 짧은 탭의 이동 누락과 연속 터치가 선택 버튼 클릭을 막는 결함을 발견해 수정했습니다.

Aside CLI/Aside Browser에서 로컬 게임 시작 화면과 새 게임 진입을 확인했고, [라운지 Play](https://lounge.letscoding.kr/works/leco/poke)가 [운영 주소](https://poke.letscoding.kr/)를 새 탭으로 여는 것을 확인했습니다. 실제 터치 기기와 운영 카카오·라운지 로그인, 계정 저장의 다른 브라우저 복구는 자동·모의 검사로 대체하지 않습니다. 현재 공유 Supabase 프로젝트는 익명 로그인이 꺼져 있어 게스트는 기기 저장을 사용합니다. 새 장 배포 결과와 현장 확인은 아래에 별도로 기록합니다.

## 세 번째 장 구현과 자동 검증

2026-10-01 로컬 구현 기준. M10·M11의 기능과 자동 검사 결과이며, M12의 실기기·운영 배포 완료 기록은 아니다.

- 기존 블루배지 저장에서 블루시티 북쪽 금빛다리·25번도로·이수재의 집으로 들어가 두 장치를 확인하고 승선권을 받았다. 남쪽 5번도로·지하통로·6번도로를 거쳐 갈색시티와 상트앙느호로 이동했다. 새 13개 맵을 포함한 총 38개 맵의 출구·문·보행 연결을 검사했다.
- 선원의 꾸러미를 선장에게 전한 뒤 체육관이 열렸다. 선택 전투를 건너뛰고 누적 도장 11개에서는 마티스 전투가 시작되지 않았으며, 실제 문제 풀이로 12개를 얻은 뒤 전투에서 이겨 오렌지배지를 받았다. 1024×768·768×1024에서 승선권·배지 저장 후 새로고침, 배지 연출 복귀, 용돈 중복 지급 방지를 확인했다.

## 네 번째 장 구현과 자동 검증

2026-10-01 구현 브랜치 기준. M13·M14의 기능·자동 검사이며, M15의 실제 기기·운영 계정·배포 완료 기록은 아니다.

- 오렌지배지 저장에서 블루시티 동쪽 → 9·10번도로 → 돌산터널 두 층 → 보라타운 → 8번도로·서쪽 지하통로·7번도로 → 무지개시티를 실제 경계·문·사다리 입력으로 통과했다. 새 15개 맵을 포함한 총 53개 맵의 무결성 8개 계약이 통과했다. `chapter3_complete` 없는 오렌지배지 저장도 새 길로 진입했다.
- 보라타운 소개 편지를 받은 뒤 로켓단에게서 씨앗상자를 되찾아 정원사에게 돌렸다. 편지 없이 대결하지 않으며, 로켓단 승리 직후 저장·재접속해도 승리 기록에서 상자 회수를 복구했다. 반복 대화에서 체육관 권한과 전투 용돈을 중복 지급하지 않았다.
- 앞선 세 배지·정원 도움·도장 15개에서는 민화 대결을 막았다. 한 과목 설정에서 실제 문제 카드로 16번째 도장을 얻은 뒤 승리해 무지개배지와 ₩2,500을 받았다. 배지 연출 도중 새로고침한 뒤 남은 연출을 재개했고, 재방문·재접속 시 보상이 늘지 않았다. 직접 `battle.trainer` 호출로도 조건을 우회하지 못했다. 로켓단·민화 패배는 각각 최근 회복 장소로 복귀하고 완료 기록이 남지 않았다.
- `npm run build`, `npm test`(9파일·102개), `npm run check:maps`(53맵·8계약), `npm run check:pokemon`(251종·753 아틀라스 셀)이 통과했다. 문제은행은 바꾸지 않았다. `npm run e2e`는 기존 세 장과 새 장·모의 카카오/비밀번호 계정 경로를 포함해 82개 중 62개 통과·20개 화면 중복 생략으로 끝났다. 이후 돌산터널 길 표시를 개선해 새 장 전체 진행 2개·5개 해상도 화면·터치 에뮬레이션 1개를 재실행해 통과했고, 로켓단 패배 복귀 1개를 추가로 통과했다.
- 화면은 1024×768·768×1024·1280×800·820×1180·375×667에서 대화·지도·체육관·배지가 넘치지 않았다. 375×667의 무지개배지와 돌산터널을 이미지로 확인했다. 모바일 터치 에뮬레이션에서 블루시티 동쪽 출구 진입과 정원사 대화를 확인했다.
- 실제 터치 기기·어린이 길찾기와 음성 사용성, 7종 스타터의 대표 파티 균형, Preview 실제 게임·Production 버전, 운영 계정의 다른 브라우저 저장 복구, 라운지 소개·Play 링크는 확인하지 않았다. M15와 기존 M9·M12 이슈에서 추적한다.
