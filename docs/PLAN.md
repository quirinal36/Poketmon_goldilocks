### 단계 4 — 통합과 E2E

1. **통합 에이전트 1개**
   - 요청 사항(Requests) 목록을 모아 반영한다.
   - `index.html`에 favicon과 apple-touch-icon 링크를 넣는다.
   - `pullSave` 병합 규칙을 연결한다.
   - 라운지 ZIP에서 `config.js`를 비운다.
   - `evolvesTo`가 2개 이상이면 진화 선택 창을 띄운다.
   - 출현 풀은 `obtainable === 'wild'`만 쓴다.
2. **맵 정적 검사 스크립트** `scripts/check-maps.mjs`
   - 행 길이
   - 범례 문자
   - 워프 목적지 좌표가 통행 가능한지
   - 출구 짝이 맞는지
   - NPC·표지판 위치
   - 스크립트 id 존재 여부
   - 트레이너 id 존재 여부
   - 문 위치와 건물 문 좌표 일치
3. **E2E 테스트** `tests/e2e/playthrough.spec.ts`
   - `?debug=1`로 실행하고, `__TEST__.autoAnswer='correct'`와 `fastText=true`를 켠다.
   - 흐름: 타이틀 → 인트로 → 방 → 연구소 → 스타팅 → 라이벌 전투 → 1번도로 풀숲 → 포획 → 상록시티 → 숲 → 회색시티 → 도장 4개 → 웅 → 배지
   - 오답 경로도 확인: `autoAnswer='wrong'`일 때 기절하면 포켓몬센터로 돌아가는지 본다.
4. **화면 크기별 스크린샷**: 5개 해상도 × 주요 화면 10개를 찍어 넘침과 겹침을 확인한다.

### 단계 5 — 검토와 수정 (반복)
서로 다른 관점의 검토자를 병렬로 돌리고, 발견된 문제는 다른 검토자가 반박 검증한 뒤 수정한다. 새 문제가 두 번 연속 나오지 않을 때까지 반복한다.

| 관점 | 확인 내용 |
|---|---|
| 아동 사용성 | 터치 크기 56px 이상, 글자 크기, 음성 읽기, 실패해도 막히지 않는지, 문장 난이도 |
| 정확성 | 저장 손상, 진도 계산, 날짜 넘김, 경험치·진화, 무한 대기(soft-lock) |
| 교육 내용 | 교육과정 순서, 난이도 곡선, 체육관 문제 수준 |
| 성능 | 60fps, 첫 로딩 용량, 메모리 |
| 한국어 | 조사, 띄어쓰기, 존댓말·반말 일관성 |

## 4. 작업 방식

### 4.1 병렬 작업 규칙
- 에이전트마다 **담당 경로**를 정하고, 다른 경로는 수정하지 않는다. 필요한 변경은 보고서의 Requests에 적는다.
- `src/core/types.ts`는 오케스트레이터만 수정한다.
- 개발 서버 포트는 에이전트마다 따로 쓴다 (5301 엔진, 5302 아트, 5307 오디오, 5309 학습, 2차는 5311~5315).
- 에이전트는 git 상태를 바꾸지 않는다. 커밋은 오케스트레이터가 단계가 끝날 때마다 한다.
- 보고서 형식: Summary / Files / Exports / Requests / Issues / Verification
